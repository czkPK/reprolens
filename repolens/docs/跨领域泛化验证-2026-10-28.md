# ReproLens 跨领域论文仓库泛化验证

## 验证目标

本验证不是在单一论文仓库上调参，而是检查同一套扫描、适用性判断、证据抽取和评分规则能否覆盖多个 AI 子领域。论文和官方仓库清单保存在 `benchmark/paper_repos.json`。

覆盖领域包括：

- 自然语言处理：BERT
- 语音识别：Whisper
- 医疗影像：MONAI
- 多模态视觉语言：CLIP
- 具身智能与机器人：Habitat
- 时间序列预测：Informer
- 计算机视觉：Vision Transformer

## 第一轮发现的问题

7 个真实仓库暴露出以下通用缺陷：

1. 只要 README 出现 OpenAI、Hugging Face、Transformers 或普通 `agents`，仓库就被误判为 LLM 项目。
2. 图像检索中的 `retrieval` 被误判为 RAG。
3. 代码许可证或模型权重许可证被误判为数据许可证。
4. Hugging Face 文档、OpenAI 博客、云存储中的协议 PDF 被误判为模型权重来源。
5. 数据仓库中真实的数据集链接可能被论文链接抢占。

这些问题会影响视觉、语音、医疗、时间序列和机器人项目，不属于某一个仓库的特例。

## 已实施的通用修复

- LLM 判定改为显式信号：只有出现 LLM、大语言模型、Prompt Template、RAG、OpenAI-compatible API、LLM Agent 等明确语义时才启用 LLM 专项检查。
- `agent` 不再单独触发 Agent 项目判定，避免把具身智能中的 embodied agents 误判为 LLM Agent。
- 图像检索中的 `retrieval` 不再触发 RAG，只有 retrieval-augmented generation、向量库、检索器等 RAG 结构才触发。
- 数据许可必须有数据上下文，代码或模型权重许可证不能替代数据许可。
- 模型来源只接受模型仓库、权重文件、checkpoint 目录或明确模型下载地址，不接受博客、文档和协议 PDF。
- 论文链接只作为论文来源，不再替代数据集或模型证据。
- 模型无关和 N/A 判断同步收紧，避免对非 LLM 仓库产生无意义的 LLM 风险扣分。

## 修复后结果

| 领域 | 仓库 | 修复前分数 | 修复后分数 | LLM 专项适用项 | 关键结果 |
|---|---|---:|---:|---:|---|
| 自然语言处理 | google-research/bert | 69.7 | 71.4 | 0 | 引用 BERT checkpoint，不再把模型许可证当数据许可 |
| 语音识别 | openai/whisper | 68.0 | 79.4 | 0 | 引用模型源码中的权重 URL，非 LLM 风险项正确关闭 |
| 医疗影像 | Project-MONAI/MONAI | 81.3 | 69.7 | 0 | 由错误的 LLM 应用判断修正为通用 AI 框架判断 |
| 多模态视觉语言 | openai/CLIP | 70.0 | 81.1 | 0 | 图像检索不再误判 RAG，模型说明与权重来源分开 |
| 具身智能与机器人 | facebookresearch/habitat-lab | 67.1 | 76.1 | 0 | 数据下载命令与数据许可正确识别，协议 PDF 不再算模型权重 |
| 时间序列预测 | zhouhaoyi/Informer2020 | 73.5 | 71.0 | 0 | 代码许可证不再冒充数据许可 |
| 计算机视觉 | google-research/vision_transformer | 75.8 | 83.2 | 0 | 引用 ViT 权重下载地址，LLM 专项检查全部 N/A |

部分仓库分数下降是修复误报后的预期结果。例如 MONAI 和 Informer 不再因为错误的许可证或 LLM 判定获得虚高分。评分的目标是更接近仓库真实证据，而不是让所有项目的分数上升。

## 验证边界

- 当前验证是静态证据审计，不等于真实训练或推理成功。
- Decision Transformer 仓库在本次服务器克隆中超时，未纳入最终表；这暴露了大仓库克隆超时和回退策略仍需继续优化的边界。
- 不同项目的 README 语言、链接形式和目录结构差异很大，后续仍需持续扩充跨领域用例。
