# ReproLens 公网网页版部署指南

## 先说明区别

- `http://127.0.0.1:8771/` 是本机网页版，只能在这台电脑上打开。
- 公网网页版会得到一个类似 `https://reprolens-xxxx.onrender.com/` 的网址，任何电脑和手机都能访问。
- ReproLens 本身不需要用户注册或登录；Render 账号只用于部署和管理服务器。

## 推荐方案：Render

仓库已经提供：

- `Dockerfile`：把 Python 网页服务打包成容器；
- `render.yaml`：告诉 Render 如何启动服务；
- `.dockerignore`：避免把测试报告和缓存打进镜像。

### 第一次部署

1. 确认代码已经推送到 GitHub：<https://github.com/czkPK/reprolens>
2. 打开 <https://render.com/>，使用 GitHub 账号登录。
3. 进入 **Dashboard → New → Blueprint**。
4. 选择 GitHub 仓库 `czkPK/reprolens`。
5. Render 会读取根目录的 `render.yaml`，点击 **Apply**。
6. 等待状态变成 **Live**。首次构建通常需要几分钟。
7. 页面顶部会显示公网网址，例如：

   ```text
   https://reprolens-xxxx.onrender.com
   ```

8. 打开该网址，输入任意公开 GitHub 仓库地址即可生成报告。

也可以直接尝试部署入口：

<https://render.com/deploy?repo=https://github.com/czkPK/reprolens>

## 验证是否部署成功

部署完成后依次检查：

1. 首页能正常打开；
2. 输入 `https://github.com/huggingface/smolagents`；
3. 能生成报告；
4. 报告中的检查项表和声明矩阵可以正常横向、纵向滚动；
5. 第一行表头和前两列保持固定；
6. 把公网报告链接复制到手机或其他电脑打开。

## 注意事项

- Render 免费服务在一段时间无人访问后会休眠，再次打开可能需要等待几十秒。
- 生成文件保存在临时目录。服务重启或重新部署后，旧报告链接可能失效；比赛演示时应现场重新生成，或同时保留本机报告。
- 公网服务不需要登录，因此任何拿到网址的人都可以提交公开 GitHub 仓库。不要在服务中配置私有令牌。
- ReproLens 只读取公开仓库，默认不执行第三方仓库代码。
- GitHub 仓库更新后，Render 可以通过 `autoDeploy: true` 自动重新部署。

## 常见问题

### 页面显示 502 或构建失败

进入 Render 的 **Logs**，检查是否出现构建错误。确认根目录存在 `Dockerfile` 和 `render.yaml`。

### 页面能打开，但分析仓库失败

检查 Render 日志中的 `git clone` 信息，并确认输入的仓库是公开仓库。系统会在克隆失败时尝试 GitHub 归档接口。

### 免费服务打开很慢

这是免费实例休眠后重新唤醒，不是网页失效。等待几十秒后刷新。

## 最终提交时怎么写网址

不要提交 `127.0.0.1` 地址。部署成功后，填写 Render 提供的公网 HTTPS 地址，例如：

```text
https://reprolens-xxxx.onrender.com
```
