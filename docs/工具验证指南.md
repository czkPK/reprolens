# ReproLens 工具验证指南

## 一、先验证“能不能跑”

1. 双击 `D:\CODEX\ReproLens\repolens\Run-Demo.cmd`。
2. 等待终端结束。
3. 浏览器应自动打开 `reports/latest/report.html`。
4. 检查报告是否包含：
   - 总分；
   - 六个维度；
   - 检查项表格；
   - 声明—证据—缺口矩阵；
   - 证据置信度和证据覆盖率；
   - Top 3 Priority Actions；
   - 可点击的证据附录；
   - ReproLens 徽章；
   - Findings；
   - 证据位置；
   - AutoFix 前后对比。

通过标准：报告能自动打开，且不是空白页。

## 二、再验证“能不能审计自己的仓库”

1. 双击 `Start-ReproLens.cmd`。
2. 选择一个本地开源仓库文件夹。
3. 等待审计完成。
4. 打开 `reports/latest/report.html`。
5. 检查报告中的证据路径是否能在仓库中找到对应文件。

通过标准：

- 能找到依赖、README、测试等基础证据；
- 每条结论都有证据 ID 或明确写“无证据”；
- 不适用项目类型能标为 N/A。

重点检查“声明—证据—缺口矩阵”：

- 每条声明是否来自 README 的真实句子；
- 是否列出需要验证的检查项；
- 是否区分 VERIFIED、PARTIALLY VERIFIED、UNVERIFIED 和 N/A；
- 缺口是否用检查项 ID 明确指出；
- 证据 ID 是否能在 Evidence Appendix 中找到。

证据覆盖率表示“适用检查项中有多少项存在关联证据”，不表示这些检查项全部通过。

检查证据追溯：

1. 在 Criteria 或 Claim Matrix 中点击任意 `E-xxx`；
2. 页面应跳到 Evidence Appendix；
3. 对应行应包含证据类型、文件路径、行号和摘录；
4. 目标行应有高亮背景。

检查徽章：

```text
reports/latest/badge.svg
reports/latest/badge.json
```

徽章应显示分数和就绪等级；JSON 应包含 commit、覆盖率和生成时间。

## 三、验证“判断是否合理”

优先检查以下项目：

- `ENV-01`：是否有 `requirements.txt`、`pyproject.toml` 或 `package.json`；
- `ENV-02`：是否有 lockfile 或 Docker 配置；
- `MODEL-02`：项目是否真的拥有自己的模型；
- `EXP-02`：是否有测试或评测命令；
- `LLM-02`：是否有 prompt 版本；
- `LLM-05`：是否有 RAG 索引/embedding 版本；
- `LLM-06`：是否有可追溯 Agent trace。

判断原则：

- 有明确证据才算通过；
- 只有部分证据算部分通过；
- 应该有但没有算缺失；
- 项目类型不需要算不适用。

## 四、验证 AutoFix 是否真的有效

打开：

```text
reports/latest/autofix/autofix.json
```

重点看：

- `before_score`
- `after_score`
- `delta`
- `generated_files`
- `rejected_files`
- `fixed_criteria`

通过标准：

- `after_score` 不会低于 `before_score`；
- 生成文件有明确理由；
- TODO/TBD/Not specified 没有被当成已验证证据；
- 修复前后分数变化可以复查。

同时打开：

```text
reports/latest/autofix/FIX_PROPOSAL.md
```

检查修复提案是否包含文件路径、原因和剩余缺口。

Action 还会写入 Job Summary，并输出 `score` 与 `badge-path`。在 PR 的 Actions 页面应能看到总分、覆盖率、前五项问题和报告 artifact。

## 五、验证工程可复现性

在 PowerShell 中执行：

```powershell
cd D:\CODEX\ReproLens\repolens
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```

通过标准：

```text
Ran 28 tests
OK
```

运行基准：

```powershell
python -m repolens.benchmark
```

查看：

- `benchmark/fresh_holdout_results.md`
- `benchmark/final_holdout_results.md`

## 六、验证安全性

默认情况下，工具只做 Python 语法解析，不运行仓库代码。

只有显式加 `--execute` 才运行：

- 脚本 `--help`
- pytest collection

检查 `reports/latest/execution.json`，确认默认探针没有执行第三方项目代码。

## 七、验证 GitHub 提交

打开：

```text
https://github.com/czkPK/reprolens
```

检查：

- 仓库是 Public；
- README 能正常显示；
- `repolens/`、`docs/`、`benchmark/` 已上传；
- 没有提交 `benchmark/repos/` 等第三方仓库源码；
- 没有 API Key、密码或个人信息。

## 八、验收结论

如果以下四项都成立，就可以认为工具达到了可提交状态：

1. Demo 和自选仓库都能输出 HTML 报告；
2. 证据路径能回到真实文件；
3. AutoFix 能给出不降低分数的修复提案；
4. 28 个单元测试通过，GitHub 仓库可公开访问。
