## 二、首轮运行暴露的问题

第一次运行时，三个仓库得分都在 86—91 分，明显偏高。检查证据后发现：

- 扫描器把整个仓库的文档、测试、示例和生成代码都当成项目级证据；
- `CHANGELOG`、`CONTRIBUTING`、`SECURITY`、API 文档中的词被误判；
- `.github` 中的开发流程 prompt 被误判为项目 prompt；
- `api.md` 中的 “embedding”“cost”“Agent” 被误判为项目自身能力；
- pre-commit 配置中的 URL 被误判为数据来源；
- tests 中的 seed 被误判为实验复现设置。

## 三、已修复的误报

已增加证据范围过滤：

- 只优先扫描根 README、明确相关的 docs、config、prompt、model card、dataset card 和主运行脚本；
- 排除 changelog、contributing、security、api.md、helpers.md、bedrock.md、tests、.github、.inline-snapshot 等噪音来源；
- prompt 文件排除 `.github` 下的开发流程 prompt；
- eval 脚本排除 tests；
- 权重文件排除 docs/tests/examples/.inline-snapshot；
- sampling/tokenizer/rag index/agent trace 只从 config 或主运行脚本提取；
- LLM-07 需要同时具备评测集、数据划分和污染风险说明才能 PASS。

修复后得分从 86—91 降到 70—82，区分度明显提高。

## 四、当前结论

1. ReproLens 已经可以在真实仓库上稳定运行；
2. 首轮真实运行证明“证据范围过滤”是必要的；
3. 当前分数还不是最终结论，因为三个人工仓库尚未完成逐项标注；
4. openai-python 是 SDK，smolagents 和 mem0 是框架/平台，不能完全代表 LLM 应用项目；
5. 下一批测试应加入真正的 LLM/RAG/Agent 应用仓库，而不是只测 SDK 和框架。

## 五、下一步

1. 对 openai-python、smolagents、mem0 各选择 10—15 个关键检查项做人工标注；
2. 再拉取 7—10 个真正的 LLM/RAG/Agent 应用仓库；
3. 计算真实 Precision / Recall / F1；
4. 根据误报继续调整证据范围；
5. 把真实运行结果写入技术报告。
